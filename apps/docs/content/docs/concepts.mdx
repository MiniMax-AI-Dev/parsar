Parsar organizes work around conversations and runs. Workspaces retain team configuration and history; Agents use a selected model and execution environment to handle requests.

## Objects you will use

| Object | Meaning | UI entry point |
| --- | --- | --- |
| Workspace | The scope that owns team members, resources, and history. | Workspace switcher at the top left. |
| Agent | A reusable name, instructions, model, capabilities, and execution configuration. | **Agents**. |
| Runtime | The device or sandbox environment executing an Agent. | **Runtime**. |
| Conversation | Continuous context containing messages and replies. | **Conversations**. |
| Run | The state, events, and results of one execution. | **Runs**. |
| Capability | Reusable instructions or tools bound to an Agent, such as a Skill or MCP server. | **Capabilities**. |
| Interaction | A request awaiting human approval or an answer. | **Inbox** and the active conversation. |
| Scheduled task | A Prompt submitted to an Agent at a configured frequency. | **Scheduled tasks**. |

## Agents, Runtimes, and Runs

For a code review request, you choose a configured Agent. It invokes a coding CLI on its bound device and creates a Run record.

The Agent is configuration, the Runtime is an execution location, and the Run is one execution. A Runtime can serve multiple Agents, and a conversation can produce multiple runs over time. Completing a Run does not close the conversation.

## Two kinds of connectors

**Agent Daemon** and **HTTP Agent** on **Runs** describe how execution is delivered. Local devices and cloud isolation use Agent Daemon. HTTP Agent is used by existing external HTTP service records; the external Agent option is currently disabled in the creation form.

Feishu, Slack, Discord, and Teams under **Integrations** are chat entry points for receiving messages and sending replies. Chat connectors and execution connectors have separate configuration and purposes. See [Agent engine comparison](/agent-tools) and [Integrations](/integrations).

## Run and interaction states

Runs have six states: Queued, Running, Completed, Failed, Cancelled, and Interrupted. The first two are active states; the last four are terminal.

Approvals and questions track their own states. While a Run shows Running, an Agent still waits for unresolved requests before continuing the affected operation. See [Runs, approvals, and logs](/runs-approvals-logs) for states and entry points.

## Sharing and permissions

A shared conversation link opens the original conversation. It does not create a copy or grant access. Workspace membership and Agent access settings determine what a user can read and execute. See [Conversations and shared conversations](/conversations) and [Members and roles](/members-roles).
