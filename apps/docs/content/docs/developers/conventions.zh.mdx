完整规范见[贡献指南](https://github.com/MiniMax-AI-Dev/parsar/blob/main/CONTRIBUTING.md)。本页列出开发时需要遵守的主要约定。

## 模块与共享逻辑

先搜索并复用已有的格式化、解析和错误映射工具。每个 API 面使用一致的错误响应；跨页面的格式化和标签由 Web 共享层维护。

服务端和 daemon 只通过共享协议交换执行数据。CLI 的进程管理留在 daemon，资源与会话的持久化留在服务端。复杂模块按职责拆分，不持续向大文件追加无关逻辑。

## 运行状态

默认配置、日志、状态和缓存保存在 `~/.parsar/`，不写入当前工作目录或代码仓库根目录。用户指定的工作目录必须是绝对路径或以 `~/` 开头。

## 生成契约

| 修改 | 必需操作 |
| --- | --- |
| API Handler 或接口定义 | 维护 swaggo 注释，运行 `make openapi` 并检查生成契约。 |
| 数据库查询 | 运行 `make sqlc-generate` 并检查生成查询代码。 |
| 数据库结构 | 新增迁移，不修改已进入 main 的旧迁移。 |
| 任意修改 | 完成前运行 `make check`。 |

生成文件随源变更一起维护，不手工编辑生成结果。

## 产品文档

文档应说明当前实现与可操作流程：给出入口、字段、动作和结果。示例参数、状态值与链接必须与当前版本一致；未开放的功能不能写成已可用的操作步骤。

中英文页成对维护。部署参数与日常使用步骤分开，开发细节集中在开发者章节。
