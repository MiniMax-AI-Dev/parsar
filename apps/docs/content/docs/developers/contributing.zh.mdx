请在独立的 Git WorkTree 和分支中工作。保留无关的用户修改；进行较大实现前先阅读根目录 `CONTRIBUTING.md`。除有意的本地化文案外，注释和文档使用英文。

## 创建 PR 前

1. 将功能分支 Rebase 到最新的 `upstream/main`，让 PR 保持线性且便于审阅的历史。
2. 保持提交聚焦，不要提交密钥、Daemon 的 `auth.json`、本地生成状态或构建产物。
3. 在 WSL/Linux 中从仓库根目录执行 `make check`。文档包还要执行 `pnpm --filter @parsar/docs typecheck` 和 `pnpm --filter @parsar/docs build`。
4. 在 PR 中说明实现内容、验证命令，以及有意延后的部署工作。

检查失败时，应在 PR 中记录准确的命令和错误，不能勾选为通过。Rebase 冲突需要逐项处理，不要用 hard reset 丢弃工作。

规范来源和生成产物契约位于 [`CONTRIBUTING.md`](https://github.com/AllureCurtain/parsar/blob/main/CONTRIBUTING.md)。
