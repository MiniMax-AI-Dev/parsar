The [contributor guide](https://github.com/MiniMax-AI-Dev/parsar/blob/main/CONTRIBUTING.md) is the source of development rules. These steps prepare a change.

## Prepare a worktree

Create a branch and Git worktree from the latest `origin/main` under `.worktrees/`. Make all changes in that worktree and preserve unrelated existing changes.

```bash
git fetch origin main
git worktree add .worktrees/my-change -b feature/my-change origin/main
```

Read the contributor guide before substantial implementation. Update it in the same branch when changing architecture rules, ownership, required checks, or generated contracts.

## Verify the change

Run from the worktree root:

```bash
make check
```

This gate includes checks for Go, the database, Web, documentation, and CLI. The documentation package can also be checked separately:

```bash
pnpm --filter @parsar/docs typecheck
pnpm --filter @parsar/docs build
```

For API or database query changes, regenerate contracts and queries as described in [Repository conventions](/developers/conventions). Record the exact command and error when a check fails; do not mark it passed.

## Review and delivery

Substantial changes require two independent reviews after implementation and verification. Reviewers inspect the requirements, acceptance criteria, project rules, and full diff. Repeat review after material fixes.

Keep commits focused and exclude secrets, runtime state, and build caches. Target PRs at `main`, explain the problem, final behavior, and validation, and complete PR review before merging.

Update English and Chinese product documentation together. Use root paths for English links and `/zh/` paths for Chinese links. Other comments and documentation use English.
