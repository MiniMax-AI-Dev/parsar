## 组成部分

| 部分 | 当前实现 | 职责 |
| --- | --- | --- |
| 服务端 | Go、Chi、PostgreSQL | 认证、授权、资源管理、运行调度、持久化和审计。 |
| 产品界面 | React、Vite | 调用 API、展示对话与运行、处理交互请求。 |
| 文档站 | Next.js、Fumadocs、MDX | 独立部署的中英文产品文档。 |
| Agent Daemon | Go 进程与编程 CLI 适配器 | 连接设备、发现引擎、管理子进程、回传事件。 |

产品界面由 Go 服务提供静态资源，文档站单独部署。数据库使用 PostgreSQL；迁移由 goose 管理，查询接口由 sqlc 生成。

## 执行与持久化

服务端保存工作区、Agent、对话、Run、能力、凭据、交互请求及引擎会话标识。Daemon 管理执行机器上的 CLI 环境、工作目录和进程，不承担对话历史的持久化职责。

Agent 连接器决定派发协议，Runtime 绑定决定目标设备，引擎类型决定调用哪个 CLI。HTTP Agent 使用外部 HTTP 服务执行；这些概念不能合并成同一个执行模式字段。

## 交互请求

审批与用户输入请求先持久化，再展示到对话、收件箱或聊天平台。各入口共用交互处理服务；Runtime 确认收到决定后，服务端才记录处理结果。运行终止会关闭尚未完成的交互，超时请求明确拒绝或取消。

## 扩展边界

新引擎复用 daemon 的进程管理和共享协议。新 Runtime Provider 管理环境的创建、续期与销毁。新聊天连接器处理平台消息和回传，不直接实现独立的权限或审批规则。

新增或调整架构边界时，同步维护[贡献规范](https://github.com/MiniMax-AI-Dev/parsar/blob/main/CONTRIBUTING.md)。
