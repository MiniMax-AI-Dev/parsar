Run 是 Agent 的一次执行记录。对话用于查看和继续交流，运行页面用于检查这次执行的状态、步骤和结果。

## 打开运行详情

1. 在左侧导航点击**运行**。
2. 找到相应的 Agent 和执行时间，点击该条 Run。顶部搜索框筛选当前页中的 Run ID、Agent 和对话 ID。
3. 详情在右侧展开，顶部显示状态、Agent、连接器、对话 ID、创建时间、开始时间、结束时间和耗时。
4. 通过底部的**打开对话**返回该次执行的对话。

## 右侧详情中的四个标签

这些标签在当前中文界面中也使用英文名称：

| 标签 | 查看内容 |
| --- | --- |
| **Overview**（概览） | 运行诊断、原因、来源、建议操作和 Runtime 健康情况。 |
| **Steps**（步骤） | 按顺序排列的运行与工具事件，默认打开此标签；可展开原始事件。 |
| **Artifacts**（产物） | 该 Run 已记录的产物名称、类型和地址；无记录时显示空状态。 |
| **Audit**（审计） | 与该 Run 关联的审计事件。 |

携带 Runtime 快照的 Run 还会展示其引擎、运行模式、模型、工作目录和心跳信息；没有快照时，概览显示缺少 Runtime 信息。HTTP Agent 不提供本地设备的引擎和工作目录字段。

**用量不在这四个标签中。** 打开**设置 → 用量 → 最近调用**，点击 **Run** 列的 ID，会跳回这里并展开对应 Run。右侧的 **Audit**（审计）不是用量入口。详见[审计与用量](/zh/audit-usage)。

## Run 状态

| 页面状态 | 值 | 含义 |
| --- | --- | --- |
| 排队中 | `queued` | 已创建，等待执行调度。 |
| 运行中 | `running` | 已被执行器接管，尚未结束；此状态本身不证明 CLI 已开始生成回复。 |
| 已完成 | `completed` | 执行已正常结束。 |
| 失败 | `failed` | 执行以错误结束，查看详情中的原因和步骤。 |
| 已取消 | `cancelled` | 此次执行已取消。 |
| 已中断 | `interrupted` | 执行被系统中断。 |

工作区所有者、管理员和成员可以对排队中或运行中的 Run 点击详情底部的**取消运行**，也可对失败的 Run 点击**重试**。重试会将同一个 Run ID 重新排队，并重置开始和结束时间。

已启动的 HTTP Agent 执行器会领取重新排队的 HTTP Run。当前**重试**不会主动派发 Agent Daemon Run，它会保留在队列中，等待其他派发触发。恢复本地设备或云端隔离的执行时，在对话中发送新消息；如果已经点击重试，先取消那条重新排队的 Run，避免之后重复执行。

当前界面也会给已取消和已中断的 Run 显示**重试**按钮，但接口会返回 HTTP 409。需要重新执行时，打开对话并发送新消息。已完成表示执行结束，仍需检查回复是否满足你的任务要求。

## Agent Daemon 和 HTTP Agent

连接器由 Agent 的执行方式决定，不能在 Run 页面修改。本地设备与云端隔离显示 **Agent Daemon**；已有的外部 HTTP 服务 Agent 显示 **HTTP Agent**。当前新建 Agent 中的外部 Agent 选项已禁用，日常使用选择设备和引擎即可。参见[Agent 引擎对照](/zh/agent-tools)。

## 审批和提问

请求入口是左侧的**收件箱**，也会出现在当前对话的时间线中。打开请求，确认操作或回答问题并提交。请求在 Runtime 确认后结束；超时后状态变为已过期，不能继续批准该请求。

请求状态与 Run 状态分开：`pending`、`resolving`、`approved`、`denied`、`answered`、`cancelled`、`expired`。秘密回答的输入方式见[对话与共享对话](/zh/conversations)。

运行长期没有进展时，检查 **Steps**（步骤）的最新事件、收件箱中的待处理请求和执行设备的日志。参见[故障排查](/zh/troubleshooting)。
