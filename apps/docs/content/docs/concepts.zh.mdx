Parsar 以对话和运行组织工作。工作区保存团队配置与历史，Agent 使用选定的模型和执行环境完成请求。

## 你会用到的对象

| 对象 | 含义 | 界面入口 |
| --- | --- | --- |
| 工作区（Workspace） | 团队成员、资源和历史的归属范围。 | 左上角工作区切换器。 |
| Agent | 可复用的名称、指令、模型、能力和执行配置。 | **Agent**。 |
| 执行环境（Runtime） | 运行 Agent 的设备或沙盒环境。 | **执行层**。 |
| 对话（Conversation） | 保存消息和回复的连续上下文。 | **对话**。 |
| 运行（Run） | 一次执行的状态、事件和结果。 | **运行**。 |
| 能力（Capability） | 绑定到 Agent 的可复用指令或工具，如 Skill 和 MCP。 | **能力**。 |
| 交互请求（Interaction） | Agent 等待人类批准或回答的问题。 | **收件箱**及当前对话。 |
| 定时任务（Scheduled Task） | 按设定频率向 Agent 提交 Prompt。 | **定时任务**。 |

## Agent、Runtime 与 Run

以“检查代码”为例：你选择一个已配置好的 Agent，它在绑定的执行设备上调用编程 CLI，并生成一条 Run 记录。

Agent 是配置，Runtime 是执行位置，Run 是一次执行。一个 Runtime 可以服务多个 Agent；同一条对话也可以先后产生多个 Run。一次 Run 完成后，对话仍可继续。

## 两类连接器

**运行**页面中的 **Agent Daemon** 和 **HTTP Agent** 描述执行的交付方式。本地设备和云端隔离使用 Agent Daemon。HTTP Agent 用于已有外部 HTTP 服务记录，当前新建表单中的外部 Agent 选项已禁用。

左侧**集成**中的飞书、Slack、Discord 和 Teams 是聊天入口，用来接收消息和返回回复。聊天连接器与 Run 的执行连接器分别配置，不能互相替代。详见[Agent 引擎对照](/zh/agent-tools)和[集成](/zh/integrations)。

## 运行状态与交互状态

Run 有六种状态：排队中、运行中、已完成、失败、已取消、已中断。前两种尚未结束，后四种是终态。

审批和提问单独记录状态。Run 显示运行中时，Agent 仍会等待尚未处理的请求；回答或批准后才能继续相应操作。具体状态及入口见[查看运行、审批和日志](/zh/runs-approvals-logs)。

## 共享与权限

共享对话链接打开的是原对话，不会创建副本，也不会给访问者增加权限。工作区成员关系和 Agent 访问设置分别决定能查看和执行的内容。详见[对话与共享对话](/zh/conversations)和[成员与角色](/zh/members-roles)。
