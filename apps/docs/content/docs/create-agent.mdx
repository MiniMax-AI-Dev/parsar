---
title: Create and configure an Agent
description: Configure the identity, connector, capabilities, model, and Runtime that an Agent uses for every run.
---

An Agent is a reusable workspace member. It holds instructions and execution configuration; it is not a permanently running process.

## Before you start

- You are a Workspace owner, admin, or member with permission to create Agents.
- At least one model is configured.
- At least one Runtime is online, or your deployment has a usable sandbox or external Agent Runtime.

## Create an Agent

1. Open **Agents** and choose **New Agent**.
2. Enter a name and optional description.
3. Choose the connector type (`agent_daemon` or `http`) and default model.
4. Choose the Runtime mode and bind the Agent to a concrete Runtime. A daemon can run on a paired local device or a managed sandbox.
5. Add a system prompt and any Capabilities the Agent needs.
6. Save the Agent.

The Runtime is part of the Agent's execution identity. `agent_daemon` dispatches streaming prompts over the reverse WebSocket; `http` calls an external Agent endpoint. There is no implicit connector conversion or silent fallback.

## Agent engine and execution options

Set `config.agent_kind` to one of the four engines advertised by the daemon: `claude_code`, `codex`, `opencode`, or `pi`. `codex` additionally supports `config.mode=default|plan`; the server clears that field when another engine is selected. Daemon mode is `local` or `sandbox`. A local mode may set an absolute `work_dir` (or a path beginning with `~/`); sandbox mode selects managed sandbox size and lifetime settings.

## Capabilities

Parsar currently models Capabilities as `skill`, `mcp`, `plugin`, `system_prompt`, or `bundle`. A Capability can require a credential; configure that credential before running the Agent.

New bindings can follow the latest Capability version or pin a specific version. Use pinning when reproducibility matters; use latest when the Agent should receive future published updates.

## Visibility and access

Agent visibility is exactly one of `workspace`, `tenant`, or `public`. `workspace` permits active members of the owning Workspace; `tenant` permits any registered Parsar user; `public` also permits unauthenticated guests. Visibility is checked before a Conversation or Run is created, and IM delivery performs the same workspace membership and policy checks.

## Verify the configuration

Open the Agent detail view and confirm:

- connector and model are present;
- the Runtime is explicitly bound and online;
- required credentials are available;
- Capabilities are enabled and not deprecated;
- the Agent is active.
