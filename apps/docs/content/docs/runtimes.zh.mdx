title: Runtime 与执行位置
description: 在执行层查看设备，区分本地设备与云端隔离。
---

Runtime 是 Agent 实际执行工作的环境。打开左侧的**执行层**（Runtime），查看接入设备、引擎版本、最后心跳和云端沙盒状态。

## 选择执行位置

在 **Agent → 新建 Agent → 执行方式**中选择：

| 方式 | 准备工作 |
| --- | --- |
| 本地设备 | 在目标机器安装编程 CLI，接入 daemon，然后选择该设备。 |
| 云端隔离 | 部署管理员配置沙盒供应商与镜像；工作区确认云端可用后选择。 |
| 外部 Agent | 当前创建选项已禁用，不能从表单新建 HTTP Agent。 |

本地设备既可以是开发者电脑，也可以是服务器或默认部署中的容器。默认 Compose 安装自带本地 Runtime，容器内已经安装编程 CLI；仍需要在 Parsar 中配置可用模型。

## 接入本地设备

工作区所有者或管理员在**执行层**点击**接入新设备**，填写名称，生成连接命令并在目标机器执行。确认设备在线且报告所需引擎后，再创建 Agent 绑定设备。完整步骤见[安装 Agent Runtime](/zh/install-runtime)。

同一台设备可以服务多个 Agent。[将命令加入 PATH](/zh/install-runtime#将命令加入-path) 后，在该机器执行 `parsar-daemon stop` 可临时停止设备；恢复时执行 `parsar-daemon connect -b`。不再使用时，先停止 daemon，再由所有者或管理员点击执行层设备行的**删除**。当前页面没有禁用设备的开关；移除设备前，需要结束的活动运行应在 Run 详情中取消。

## 设备状态

| 状态 | 含义 |
| --- | --- |
| 等待配对 | 已生成设备记录，尚未完成连接。 |
| 在线 | 服务端正在收到设备心跳。 |
| 离线 | 心跳已中断，无法确认设备可用。 |
| 错误 | 设备上报错误，检查 daemon 日志。 |

daemon 默认每 **15 秒**发送心跳，服务端超过 **60 秒**未收到心跳就判定离线。在线状态与 Agent 的模型认证是两件事，最终以一次实际 Run 的结果验证配置。

## 云端隔离

执行层下方展示云端沙盒供应商、工作区 E2B Key 和运行实例。工作区管理员可以在这里录入或更换 Key；保存工作区 Key 并不能替代部署端启用沙盒。

当前部署需要 `AGENT_DAEMON_SANDBOX_TEMPLATE` 和部署级 `PARSAR_E2B_API_KEY` 才会初始化沙盒执行器，并且 `PARSAR_PUBLIC_URL` 必须能从沙盒内访问。配置缺失时由部署管理员补齐，不能仅靠在 Agent 表单中选择云端隔离解决。

沙盒按 Agent 复用，不会在每个 Run 完成后立即销毁。回收实例会终止其中的工作；下一次请求重新创建执行环境。

## 定位一次执行

打开**运行 → 对应 Run → Overview**（概览），检查这次执行记录的 Runtime 信息。Agent 使用指定环境，不会在设备故障后自动换到其他电脑。排队或失败时，继续查看 **Steps**（步骤）和[故障排查](/zh/troubleshooting)。
