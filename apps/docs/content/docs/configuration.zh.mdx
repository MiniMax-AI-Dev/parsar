description: 通过 YAML、环境变量和部署模板配置 Parsar。
---

Parsar 按以下顺序加载配置：内置默认值、`PARSAR_CONFIG_FILE` 指向的 YAML、环境变量。环境变量为空时不会清除 YAML 中已有的非空值。配置路径必须是绝对路径或以 `~/` 开头；服务端不会回退到当前工作目录。

## 服务端配置

当前服务端支持的进程变量如下：

| 分组 | 变量 |
| --- | --- |
| 服务端 | `PARSAR_CONFIG_FILE`、`PARSAR_ADDR`（默认 `:8080`）、`PARSAR_PUBLIC_URL`、`PARSAR_DATA_DIR`（默认 `~/.parsar`） |
| 数据库与密钥 | `DATABASE_URL`、`PARSAR_MASTER_KEY` |
| 开发与认证 | `PARSAR_DEV_AUTH`、`PARSAR_PLATFORM_ADMIN_USER_IDS`、`PARSAR_LOGIN_REDIRECT_URL` |
| Agent 执行 | `PARSAR_OPENCODE_BIN`、`PARSAR_OPENCODE_RUNNER`、`PARSAR_PLUGIN_HOST_PATH` |
| 飞书 | `PARSAR_FEISHU_MOCK`、`PARSAR_FEISHU_APP_ID`、`PARSAR_FEISHU_APP_SECRET`、`PARSAR_FEISHU_REDIRECT_URI`、`PARSAR_FEISHU_SCOPE`、`PARSAR_FEISHU_AUTHORIZE_BASE`、`PARSAR_FEISHU_API_BASE`、`PARSAR_FEISHU_VERIFICATION_TOKEN`、`PARSAR_FEISHU_ENCRYPT_KEY` |
| 审计 | `PARSAR_AUDIT_OTLP_ENABLED`、`PARSAR_AUDIT_OTLP_ADDR`（默认 `:4318`）、`PARSAR_AUDIT_OTLP_SIGNING_KEY`、`PARSAR_AUDIT_OTLP_EXTERNAL_ENDPOINT`、`PARSAR_AUDIT_OTLP_FANOUT_ENDPOINT` |
| 存储 | `PARSAR_BLOB_BACKEND`（`pg` 或 `oss`）、`PARSAR_OSS_REGION`、`PARSAR_OSS_ENDPOINT`、`PARSAR_OSS_BUCKET`、`PARSAR_OSS_ACCESS_KEY_ID`、`PARSAR_OSS_ACCESS_KEY_SECRET`、`PARSAR_OSS_BASE_URL` |

YAML 对应字段见 [`docs/deploy/config.example.yaml`](https://github.com/MiniMax-AI-Dev/parsar/blob/main/docs/deploy/config.example.yaml)：`server`、`database`、`auth`、`secret`、`gateway.feishu`、`model`、`storage`、`audit.otlp`。密钥应放在环境变量或密钥管理器中。生产校验要求 public URL、Postgres URL、master key 和安全 Cookie；开发模式必须显式使用受支持的开发开关。

示例中的具体键包括：`server.addr`、`server.public_url`、`server.data_dir`、`server.plugin_host_path`、`database.url`、`auth.dev_auth`、`auth.cookie.secure`、`auth.platform_admin_user_ids`、`secret.master_key`、`gateway.feishu.mock`、`gateway.feishu.app_id`、`gateway.feishu.app_secret`、`gateway.feishu.redirect_uri`、`gateway.feishu.scope`、`gateway.feishu.authorize_base`、`gateway.feishu.api_base`、`gateway.feishu.verification_token`、`gateway.feishu.encrypt_key`、`gateway.feishu.login_redirect_url`、`model.opencode_bin`、`sandbox.runner`、`storage.blob_backend`、`storage.oss.region`、`storage.oss.endpoint`、`storage.oss.bucket`、`storage.oss.access_key_id`、`storage.oss.access_key_secret`、`storage.oss.base_url`、`audit.otlp.enabled`、`audit.otlp.addr`、`audit.otlp.signing_key`、`audit.otlp.external_endpoint` 和 `audit.otlp.fanout_endpoint`。部分版本的渲染示例会省略 `server.plugin_host_path`，但 loader 仍支持该键。

模板变量是 Compose 接线，不是 Agent 字段。复制为 `.env` 后替换占位符，绝不提交生成的文件。

## 连接器进程开关

即时通讯 worker 通过进程开关启用：飞书使用 `PARSAR_FEISHU_WS_REFRESH_SECONDS` 和 `PARSAR_FEISHU_OUTBOUND_POLL_SECONDS`；Slack Socket Mode 使用 `PARSAR_SLACK_SOCKET=true`、`PARSAR_SLACK_BOT_TOKEN`、`PARSAR_SLACK_APP_TOKEN`；Discord Gateway 使用 `PARSAR_DISCORD_GATEWAY=true`、`PARSAR_DISCORD_BOT_TOKEN`；Teams webhook 使用 `PARSAR_TEAMS_WEBHOOK=true`、`PARSAR_TEAMS_APP_ID`、`PARSAR_TEAMS_APP_PASSWORD`。数据库多租户 reconciler 通过 `PARSAR_SLACK_CONNECTORS`、`PARSAR_DISCORD_CONNECTORS`、`PARSAR_TEAMS_CONNECTORS` 启用，具体 master key 要求见各集成页。

## 安全变更

- 更换 master key 前备份数据库；旧密文无法用新密钥解密。
- public URL 必须与反向代理和 OAuth 回调一致。
- 生产挂载路径使用仓库之外的绝对路径。
- 修改启动时 Provider 开关后重启服务，并检查 `/healthz` 与 `/readyz`。
