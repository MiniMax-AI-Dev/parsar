---
title: 令牌与凭据
description: 区分登录会话、设备配对令牌和模型或工具使用的凭据。
---

Parsar 为登录、设备连接和外部服务使用不同凭据。日常操作在对应页面完成，不需要把浏览器 Cookie 复制到命令行。

## 在哪里管理

| 凭据 | 入口 | 用途 |
| --- | --- | --- |
| 登录会话 | 登录页；用户菜单中的**退出登录** | 保持当前浏览器登录状态。 |
| 设备配对令牌 | **执行层 → 接入新设备 → 生成连接命令** | 将目标机器连接到当前工作区。 |
| 模型 Key | 左侧**模型** | 访问选定的模型服务。 |
| 个人和组织凭据 | **设置 → 凭据** | 向能力、模型和运行环境提供外部服务凭据。 |
| 聊天机器人凭据 | 左侧**集成** | 连接飞书、Slack、Discord 或 Teams。 |

## 浏览器会话

登录后浏览器保存 `parsar_session` Cookie。默认有效期为 **30 天**，使用会话不会延长原定过期时间。退出登录会撤销当前服务端会话。部署管理员应使用 HTTPS 提供服务。

## 设备配对令牌

生成连接命令时创建的令牌以 `rtk_` 开头，有效期为 **15 分钟**，成功配对一次后失效。服务端只保存其哈希。

配对成功后，daemon 获得以 `rtc_` 开头的运行凭据，用于维持设备连接。配对令牌和运行凭据不能替代用户登录。

配对成功后，运行凭据保存在 `~/.parsar/parsar-daemon/<profile>/auth.json`，文件权限为 `0600`；默认 profile 为 `default`。后台进程的日志和 PID 保存在同一目录，文件名为 `connect.log` 和 `connect.pid`。设置 `PARSAR_HOME` 后，该值替代 `~/.parsar` 基础目录。

停止 daemon 或重启机器后，执行 `parsar-daemon connect -b` 复用有效的已保存凭据。这些命令需要先[将二进制加入 PATH](/zh/install-runtime#将命令加入-path)，或改用下载文件的完整路径。不再使用的设备，先停止 daemon，再由所有者或管理员在**执行层**删除设备。`parsar-daemon logout` 只删除本地凭据。

## 模型和工具凭据

模型 Key、组织凭据、个人凭据和聊天机器人 Secret 在服务端加密保存。界面展示名称、状态及掩码，不提供读取已保存明文的入口。

更换外部服务令牌后，在对应模型、凭据或集成页面更新值，并重新运行一次相关任务。个人凭据按使用者解析，组织凭据供工作区配置引用，操作步骤见[模型与凭据](/zh/models-credentials)。

`PARSAR_MASTER_KEY` 是部署加密主密钥，不是用户 API Key。备份数据库时安全备份该密钥；直接更换它会使旧凭据无法解密。

## 交互中的秘密回答

Agent 将问题标记为敏感时，对话或收件箱中的自由输入框会遮蔽答案。答案传给等待中的 Agent，Parsar 保存的交互响应、相关运行事件和审计记录会脱敏。这不改变 Agent 及其所用工具接收到的值，详见[交互请求](/zh/conversations)。

不要在普通消息、运行产物或问题截图中粘贴配对令牌和 API Key。
