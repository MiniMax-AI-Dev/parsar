---
title: Scheduled tasks
description: Schedule Agent work with frequency, time, and timezone controls, then inspect the result.
---

A scheduled task sends its saved Prompt to one Agent. Each trigger creates a separate conversation and Run. Results remain available in **Conversations** and **Runs**.

## Create a task

Owners, admins, and members can manage scheduled tasks. Viewers can only read them.

1. Open **Scheduled Tasks** in the sidebar and click **New task**.
2. Enter a **Task name** and choose an enabled **Agent**.
3. Enter the **Prompt** describing the work to perform each time.
4. Select the **Frequency** and time. Preset schedules use form controls, without requiring cron text.
5. Choose a **Timezone**, review the schedule preview, and click **Save**.

| Frequency | Time controls |
| --- | --- |
| Daily / Weekdays | Time of day; weekdays means Monday through Friday. |
| Weekly | Day of week and time. |
| Monthly | Day of month and time. |
| Hourly | Minute. |
| Custom | A five-field cron expression: minute, hour, day, month, weekday. |

For a daily run at 09:00 Beijing time, choose **Daily**, **09:00**, and **Asia/Shanghai**. The list's `0 9 * * *` is the generated representation of that schedule.

New tasks are enabled when saved, and the list shows **Next run**. The timezone initially comes from the browser; verify it before saving. Editing changes the name, Prompt, and schedule, but not the execution Agent.

## Run now and inspect results

1. Click the play icon on the task row, labeled **Run now** on hover.
2. The confirmation means an execution request was created; it does not mean the Agent has finished.
3. Open **Runs** in the sidebar, find the new record by Agent and time, and open **Steps** in its right-hand details.
4. When execution ends, the Run shows **Completed**, **Failed**, **Cancelled**, or **Interrupted**. Click **Open conversation** to read the reply.

The scheduled-task list currently does not continuously poll execution results. While it stays open, its status icon retains the last loaded value. Reload the page to fetch the latest status. A stale Running icon alone does not establish that execution is stuck.

## Manage the schedule

Each row offers **Edit**, **Run now**, enable or disable, and **Delete**. Disabling stops future automatic triggers but still allows a manual run. Deleting preserves historical Runs. The creation form has no disabled-state option; save the task first, then disable it.

Both automatic scheduling and **Run now** prevent overlap while the previous Run is queued or running. A repeated manual trigger returns `a run is already active for this task` and creates no new Run. Wait for the active Run to finish, or cancel it in Run details, before triggering again. Manual execution does not change the next scheduled time.

At the next due time, the scheduler inspects the previous result. Failure, cancellation, or interruption increments the consecutive-failure count; completion resets it. After **five** failures, the task is disabled automatically. A manual trigger does not immediately change that counter. Fix the error before re-enabling the schedule.

## Investigate a long-running task

Check the Run's latest steps, pending Inbox requests, and device status. A real Agent waits for model and tool work; a test Agent's fixed reply does not establish the duration of a real task. With no new events, start with the Run checks in [Troubleshooting](/troubleshooting).
