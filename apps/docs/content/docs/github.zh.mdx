title: GitHub 集成

Parsar 支持在工作区设置中连接用户的 GitHub 账号。该集成提供给 Agent 和能力使用的是个人 OAuth 凭据，并不是 GitHub App 安装，也不是 Pull Request 同步服务。

## OAuth 流程

服务端使用配置的 GitHub 客户端启动授权流程，并在回调时校验 `parsar_github_oauth_state` Cookie。默认 scope 为 `repo read:user user:email`。可以使用以下环境变量覆盖授权地址、API 地址、回调地址和 scope：

| 变量 | 用途 |
| --- | --- |
| `PARSAR_GITHUB_CLIENT_ID` | OAuth 应用客户端 ID |
| `PARSAR_GITHUB_CLIENT_SECRET` | OAuth 应用密钥 |
| `PARSAR_GITHUB_REDIRECT_URI` | 对外可访问的回调地址 |
| `PARSAR_GITHUB_SCOPE` | 以空格分隔的 scope 覆盖值 |
| `PARSAR_GITHUB_AUTHORIZE_BASE` | GitHub 或 GitHub Enterprise 授权地址基址 |
| `PARSAR_GITHUB_API_BASE` | GitHub API 基址 |

回调会获取账号资料，并保存一个 `github_pat` 凭据，其中包含令牌、令牌类型、已授予的 scope、登录名、GitHub ID、显示名称、头像地址和服务商元数据。Parsar 使用 `PARSAR_MASTER_KEY` 加密凭据，令牌不会写入会话消息或普通日志。

## 当前边界

当前 UI 将此集成描述为访问公开 GitHub 仓库。私有仓库访问、SSH 密钥、GitLab，以及 GitHub App/PR 自动化并未在当前产品界面实现。在代码中没有对应 API 之前，不要把仓库 Webhook、PR 审查闭环或 VCS 服务商矩阵写进文档。

如果回调失败，请检查对外回调地址、客户端凭据、状态 Cookie，以及到配置的 GitHub API 的出站网络。若 Parsar 凭据泄露，应先在 GitHub 撤销 OAuth 令牌，再删除凭据。

参阅[令牌与凭据存储](/zh/authentication-tokens)、[能力](/zh/capabilities)和[配置参考](/zh/configuration)。
