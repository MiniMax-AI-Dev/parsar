---
title: Agent 引擎对照
description: 创建 Agent 时如何选择 Claude Code、Codex 或 pi。
---

Agent 引擎是在执行设备上实际完成工作的编程 CLI。选择入口是 **Agent → 新建 Agent → Agent 引擎**；查看已有配置时打开 Agent 详情。

## 当前可选引擎

| 引擎 | 新建 Agent 时可选 | 权限请求 | 会话恢复 | 用量上报 |
| --- | --- | --- | --- | --- |
| Claude Code | 是 | 支持 | 支持 | 支持 |
| Codex | 是 | 支持 | 支持 | 支持 |
| pi | 是 | 不提供交互审批 | 支持 | 支持 |
| OpenCode | 选项已禁用 | 不支持 | 不支持 | 支持 |

OpenCode 的适配器仍可出现在已有设备或 Agent 记录中，但当前创建表单不能选用它。各引擎的用量来自 CLI 上报；未上报的数值不会被 Parsar 自动补算为服务商账单。

Codex 还提供协作模式选择。需要 Agent 使用用户输入提问工具时，选择 **Plan** 模式；普通提示词不会开启该模式专属工具。

## 在哪里安装

本地设备：在所选设备上，按 CLI 官方说明安装，并确保 daemon 的运行账号可以找到它。Parsar 中选择引擎不会替你在设备上安装 CLI。

云端隔离：编程工具由部署使用的沙盒镜像提供。工作区选择 Agent 引擎和模型；镜像与供应商配置由部署管理员维护。

设备接入后，打开**执行层**查看每台设备报告的引擎和版本。完整连接流程见[安装 Agent Runtime](/zh/install-runtime)。

## 引擎、设备和连接器

- **Agent 引擎**回答“使用哪个编程工具”。
- **执行设备**回答“在哪台机器上运行”。
- Run 的**连接器**列回答“Parsar 用什么方式交付这次执行”。本地设备和云端隔离使用 **Agent Daemon**。

**HTTP Agent** 是外部 HTTP 服务的执行方式，不是可安装的编程 CLI。当前 **外部 Agent** 创建选项已禁用；已有 HTTP Agent 记录仍会在运行列表中显示。普通用户无需寻找单独的 HTTP Agent 配置页面。

## 能力不生效时

打开 **运行 → 对应记录 → Steps**（步骤），检查能力解析和执行错误；再检查 Agent 绑定的能力版本及所需凭据。引擎之间的 Skill、MCP 和 Plugin 支持不同，不要只凭能力已绑定就判断执行工具已加载。

参见[能力、Skill 与 MCP](/zh/capabilities)和[查看运行、审批和日志](/zh/runs-approvals-logs)。
