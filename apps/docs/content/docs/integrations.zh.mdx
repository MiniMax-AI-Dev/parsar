---
title: 聊天集成
description: 从集成页面连接飞书、Slack、Discord 和 Microsoft Teams。
---

聊天集成让团队从消息平台向 Agent 发送请求，执行记录仍保存在 Parsar 的对话和运行中。

## 从哪里进入

选择工作区，点击左侧的**集成**。页面列出四个平台，点击平台行后，配置面板在右侧展开。只有工作区所有者和管理员可以修改配置。

| 平台 | 当前配置方式 |
| --- | --- |
| [飞书](/zh/feishu) | 扫码授权，自动保存工作区机器人连接。 |
| [Slack](/zh/slack) | 填写 App ID、Bot Token 和 App-Level Token，使用 Socket 模式。 |
| [Discord](/zh/discord) | 填写 Application ID、Bot Token 和 Public Key。 |
| [Microsoft Teams](/zh/teams) | 填写 App ID、应用密码，部署管理员启用 webhook 接收端。 |

这里管理的是**工作区机器人**。飞书还提供单个 Agent 的机器人入口，见[飞书](/zh/feishu)。模型在左侧的**模型**配置，设备在**执行层**接入，MCP 在**能力**中添加；这些不属于聊天平台连接器。

## 如何判断配置完成

Slack、Discord 和 Teams 在表单中打开启用开关后保存；关闭开关保存的是草稿。飞书扫码授权成功后自动保存并启用。

列表状态包括**已启用**、**已配置**、**未完整**、**未配置**。这是已保存配置的状态，不是一次真实消息收发的测试结果。完成配置后，还要从聊天平台验证消息能够触发预期 Agent，并在 Parsar 中查看对应 Run。

## 身份与工作区

机器人接收消息后，会检查发送者的 Parsar 身份、工作区成员关系和目标 Agent 的访问权限。保存机器人凭据不会自动把平台里的所有人加入工作区。

飞书用户可以通过已配置的飞书登录关联身份。Slack、Discord 和 Teams 当前没有面向用户的自助身份绑定页面；使用前需要部署管理员准备平台身份映射。只有保存连接器配置，尚不能完成这些平台的新用户接入。

聊天网关是 Parsar 服务中的消息接收和路由功能；它由集成面板保存的连接器配置和服务端部署共同提供，没有单独的用户配置页面。

## 修改凭据或停用

Slack、Discord 和 Teams 可以在原配置面板中输入新凭据并保存，或关闭启用开关后保存。已保存秘密的输入框保持空白并显示已保存标记，留空会保留原值。飞书面板提供**重新扫码**，当前没有单独的断开按钮。

已有对话和 Run 不会因为修改连接器配置而删除。部署需要稳定的加密密钥，见[部署配置](/zh/configuration)。
