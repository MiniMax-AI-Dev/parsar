---
title: 创建和配置 Agent
description: 配置 Agent 的身份、连接器、能力、模型和 Runtime。
---

Agent 是工作区中的可复用成员。它保存指令和执行配置，但不是一个永久运行的进程。

## 开始前准备

- 你具备创建 Agent 所需的 Workspace Owner、管理员或成员权限。
- 至少配置了一个模型。
- 至少有一个 Runtime 在线，或者部署提供可用的沙盒 / 外部 Agent Runtime。

## 创建 Agent

1. 打开 **Agent**，点击 **新建 Agent**。
2. 填写名称和可选描述。
3. 选择连接器类型（`agent_daemon` 或 `http`）和默认模型。
4. 选择 Runtime 模式，并把 Agent 绑定到具体 Runtime。daemon 可以运行在已配对的本地设备或托管沙盒中。
5. 添加 System Prompt 和 Agent 需要的能力。
6. 保存 Agent。

Runtime 是 Agent 执行身份的一部分。`agent_daemon` 通过反向 WebSocket 派发流式 prompt；`http` 调用外部 Agent 地址。连接器不会自动转换，也不会静默回退。

## Agent 引擎与执行选项

`config.agent_kind` 必须是 daemon 宣布的四种引擎之一：`claude_code`、`codex`、`opencode` 或 `pi`。`codex` 额外支持 `config.mode=default|plan`；切换到其他引擎时服务端会清除该字段。daemon 模式是 `local` 或 `sandbox`。本地模式可以设置绝对 `work_dir`（或以 `~/` 开头的路径）；沙盒模式选择托管沙盒的大小和生命周期设置。

## 能力

Parsar 当前支持的 Capability 类型包括 `skill`、`mcp`、`plugin`、`system_prompt` 和 `bundle`。如果能力需要凭据，请在运行 Agent 前完成配置。

新绑定可以跟随最新 Capability 版本，也可以固定到指定版本。需要可复现时使用固定版本；希望自动获得后续发布版本时使用 latest。

## 可见性和访问权限

Agent 可见性只有 `workspace`、`tenant`、`public` 三种。`workspace` 允许所属工作区的 active 成员；`tenant` 允许任意已注册 Parsar 用户；`public` 还允许未登录访客。服务端会在创建 Conversation 或 Run 前检查可见性，即时通讯入口也执行相同的工作区成员和策略检查。

## 检查配置

打开 Agent 详情，确认：

- 已选择连接器和模型；
- 已明确绑定且在线的 Runtime；
- 所需凭据可用；
- Capability 已启用且未废弃；
- Agent 状态为 active。
