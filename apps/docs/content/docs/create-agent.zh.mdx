title: 创建和配置 Agent
description: 为 Agent 选择模型、引擎、执行设备和能力。

Agent 保存名称、指令、模型和执行配置。设备负责运行 Agent；一次请求产生的执行记录叫 Run。

## 开始前准备

准备一个已通过连接测试的[模型](/zh/models-credentials)，以及支持所选引擎的在线[执行设备](/zh/install-runtime)。只有工作区所有者和管理员可以创建 Agent。

## 创建 Agent

1. 点击左侧 **Agent → 新建 Agent**。
2. 填写名称和可选描述。
3. 在**执行方式**中选择**本地设备**或**云端隔离**。外部 Agent 选项当前已禁用。
4. 选择 **Agent 引擎**：Claude Code、Codex 或 pi。OpenCode 当前不可选。
5. 本地设备需要选择与引擎兼容的设备；云端隔离需要部署已配置沙盒。
6. 选择模型。出现 **Model 凭据**区域时，选择**使用共享 API key**，再选择已有共享密钥或新建一条。
7. 填写指令和需要的能力配置，保存。

本地设备选择器会过滤不支持当前引擎的设备。切换引擎后设备列表为空时，先到**执行层**检查设备报告的工具。

## 工作目录

工作目录是执行设备上的路径，不是浏览器所在电脑的路径。当前 Agent 表单要求以 `/` 开头的绝对路径，例如 `/home/me/projects/demo`。使用 WSL 时填写 WSL 中的路径，例如 `/mnt/d/projects/demo`。

填写完整路径，不要使用相对路径或 `~/project`。目录不存在时，执行引擎会自动创建；运行 daemon 的操作系统账号必须有权创建和访问该目录。

## 修改配置

点击 Agent 打开详情，在**配置**中查看模型、Prompt、引擎、设备和能力。修改模型、Prompt、引擎或设备时，点击详情底部的**编辑**，修改表单后点击**保存**。Codex 的协作模式提供 Default 和 Plan；需要使用用户输入提问工具时选择 Plan。

Agent 的连接器取决于创建时的执行方式。本地设备和云端隔离使用 Agent Daemon，不能通过修改某条历史 Run 改变连接器。

能力绑定直接在**配置**中管理，可以跟随最新版本或固定版本。具体添加流程见[能力、Skill 与 MCP](/zh/capabilities)。

## 可见性

当前**新建 Agent**表单固定创建**公开** Agent（`public`），没有可见性选择器，编辑表单也不能修改可见性。已有 Agent 记录还支持**工作区**和**全租户**范围（`workspace`、`tenant`）。

公开 Agent 不能使用调用者各自的个人模型凭据。请选择自带共享 Key 的模型，或在引用凭据的模型下通过 **Model 凭据**绑定共享密钥。详见[模型与凭据](/zh/models-credentials)。

Agent 公开不会发布它已有的对话；已有对话仍按其所属工作区检查访问权限，见[共享对话](/zh/conversations)。

## 验证

保存后点击**聊一下**，发送一个小范围请求。打开**运行**，确认使用的 Agent、执行位置和最终状态，再开始真实工作。

参见[Agent 引擎对照](/zh/agent-tools)和[查看运行、审批和日志](/zh/runs-approvals-logs)。
