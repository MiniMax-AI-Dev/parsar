---
title: 模型与凭据
description: 配置模型端点，并让 Provider 凭据保持加密和最小范围。
---

模型决定一次 Agent Run 由哪个 Provider 处理；凭据决定 Parsar 或选中的 Runtime 能否通过 Provider 认证。两者相关，但不是同一个资源。

## 配置模型

1. 打开**设置 → 模型**。
2. 添加或选择模型端点和 Provider 协议。
3. 选择 Provider 所需的凭据绑定。
4. 如果页面提供测试诊断，先执行测试。
5. 将模型设置为 Agent 的默认模型。

Agent 保存的是模型引用，Secret 不会复制到 Agent 的公开配置中。Provider Base URL 和模型标识应明确填写，便于复现 Run。

## 凭据范围

根据凭据表单，Secret 可能属于个人、工作区，或绑定到某个 Capability/Agent。只授予满足工作流所需的最小范围。界面中的掩码预览不是 Secret 本身，不能据此还原原值。

## 轮换和失败

先在 Provider 侧轮换 Key，再更新 Parsar 中对应凭据。历史 Run 会保留当时的元数据，后续 Run 使用新凭据。常见问题包括凭据缺失、Provider 权限无效、限流、模型不可用和 Base URL 错误。

## 安全检查

- 不要把 Provider Key 写入 Agent Prompt、Skill 或源文件；
- 报告模型问题时不要上传完整环境变量；
- 启用 Scheduled Task 或聊天网关前，先用低风险 Agent 测试；
- 检查 Run 的 Runtime 快照，确认实际使用的 Provider 和模型。
