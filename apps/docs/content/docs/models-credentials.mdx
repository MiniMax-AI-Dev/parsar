---
title: Models and credentials
description: Add a model, test its endpoints, and manage personal and organization credentials.
---

A model records its service URL, identifier, and API protocol. Credentials authenticate requests. Configure and test a model before selecting it for an Agent.

The model catalog is shared across the whole Parsar instance. Switching workspaces shows the same model records. Changes to a model also affect Agents in other workspaces that use it.

## Add a model

1. Open **Models** in the sidebar and click **New model**.
2. Select a provider and enter the model name and Model Key. Use an identifier the provider actually accepts.
3. Confirm the service URL and API protocol. For a model supporting several interfaces, check each protocol's endpoint URL.
4. Choose a credential mode. Enter an API key for a shared-key model; for personal credentials, select the required credential kind and prepare your personal credential.
5. Save the model.

Editing can change model information and URLs, but cannot switch credential mode. Create another model record to use a different mode.

## Test the model

Find the model in the list and use **Test connection**. The diagnostic view shows each endpoint's result. Inspect errors to distinguish URL, protocol, authentication, and model-identifier problems.

After a successful test, select the model in **Agents → New Agent**. For an existing Agent, open its details, click **Edit** at the bottom, select the model, and **Save**. Model connectivity and a full Agent Run are separate checks; the execution device and coding CLI must also work.

## Bind credentials to an Agent

The current **New Agent** form always creates a Public Agent, so **Each caller's own API key** is disabled. A model with a shared key can be selected directly. For a model configured with a credential reference, choose **Use a shared API key** under **Model credential**, then select an existing shared key or create one in the form.

Preparing only your personal credential does not complete this new-Agent setup. Existing non-public Agents can use each caller's personal credential; each caller must supply the credential kind required by the model.

## Manage credentials

### Personal credentials

Open **Settings → Credentials → Mine**, click **Add credential**, select a credential kind, and complete its fields. Existing rows provide **Edit** to replace values and **Delete** to remove the credential. These credentials belong to your account and are reused across workspaces; other members cannot read them.

### Organization credentials

Workspace owners and admins open **Settings → Credentials → Org-shared**. Click **Add API Key**, choose Runtime or Custom API as the purpose, enter Name, Provider, and API Key, then save.

This tab has no general edit action for saved keys. Model keys link to **Open Models**; update them on the model's edit form. Manage the workspace E2B key in **Runtime**. For a shared key bound to an Agent or capability, create a replacement, update the resource's credential binding, verify a Run, then disable the old key.

Saved values expose only metadata or a masked preview; the preview is not the original key. Keep API keys out of Prompts, Skills, and ordinary conversations.

When a capability requires a personal credential, each user must provide their own. An administrator saving an organization credential does not complete every user's personal authentication.
