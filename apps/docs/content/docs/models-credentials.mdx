---
title: Models and credentials
description: Configure model endpoints and keep provider credentials scoped and encrypted.
---

Models determine which provider handles an Agent Run. Credentials determine whether Parsar or the selected Runtime can authenticate to that provider. They are related, but they are not the same resource.

## Configure a model

1. Open **Settings → Models**.
2. Add or select a model endpoint and provider protocol.
3. Choose the credential binding expected by the provider.
4. Use the model test diagnostics when available.
5. Select the model as the Agent's default model.

The Agent stores a reference to the selected model; secret values are not copied into its public configuration. Keep provider base URLs and model identifiers explicit so a Run can be reproduced.

## Credential scopes

Depending on the credential form, a secret may be personal, workspace-wide, or bound to a capability or Agent. Grant the narrowest scope that satisfies the workflow. A masked preview in the UI is not the secret value and cannot be used to reconstruct it.

## Rotation and failures

Rotate a key in the provider first, then update the corresponding Parsar credential. Existing Run records retain their metadata, but future Runs use the new credential. Common failures include missing credentials, invalid provider access, rate limits, unavailable models, and incorrect base URLs.

## Safety checklist

- Do not put provider keys in Agent prompts, Skills, or source files.
- Do not share a full environment dump when reporting a model problem.
- Test with a low-risk Agent before enabling a scheduled task or chat gateway.
- Check the Run's runtime snapshot to confirm which provider and model were actually used.
