---
title: 工作区
description: 了解 Parsar 中的工作区边界、成员关系和生命周期。
---

工作区是 Parsar 的租户边界。Agent、对话、运行、Runtime、Capability、凭据、定时任务和审计记录都属于某个工作区。

## 工作区包含什么

| 范围 | 工作区内的数据 |
| --- | --- |
| 团队 | 成员、角色、邀请和加入申请 |
| Agent | 身份、连接器、可见性、能力和 Runtime 绑定 |
| 执行 | Conversation、Run、审批、产物和用量记录 |
| 运维 | Runtime、daemon 配对、定时任务和审计事件 |
| 配置 | 模型、凭据、Secrets、连接器和导入的能力 |

API 请求首先会检查工作区边界。切换工作区只会改变当前查看范围，不会移动或复制数据。

## 创建工作区

1. 登录 Parsar。
2. 如果账号还没有任何成员关系，按照首次引导创建第一个工作区。
3. 如果已经加入工作区，打开工作区切换器并选择**创建工作区**。
4. 输入展示名称，并选择 `private` 或 `public` 可见性。

创建者会自动成为初始 `owner`。私有工作区只能通过邀请加入；公开工作区可以出现在发现列表中，并根据服务端注册策略接受加入申请。

## 切换、加入和离开

工作区切换器会列出账号当前拥有 active 成员关系的工作区。公开工作区可以通过发现和申请流程加入；owner 或 admin 可以批准或拒绝待处理的加入申请。

离开工作区会移除当前成员关系。离开前应确认团队仍然需要的 Runtime 和 Agent 配置已经由其他成员接管。最后一名 owner 不能直接离开，必须先将其他成员提升为 owner。

## 更新和归档

Owner 和 admin 可以修改工作区元数据。归档是软生命周期操作：工作区不再作为普通 active 工作区使用，但服务端记录会按照保留策略保留。涉及破坏性操作时，应以当前确认对话框显示的内容为准。

## 权限边界

成为工作区成员并不自动意味着可以运行任意 Agent。系统还会独立检查 Agent 的可见性与 Access、选中的 Runtime 以及所需凭据。参见[成员与角色](/zh/members-roles)、[创建和配置 Agent](/zh/create-agent)和[能力](/zh/capabilities)。
