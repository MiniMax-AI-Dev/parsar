title: 对话与共享对话
description: 开始对话、复制对话链接，并回答 Agent 的提问。
---

对话保存你与 Agent 的消息和回复。同一条对话可以连续发送多条消息，每次执行的状态和事件记录在对应的 Run 中。

## 开始对话

1. 打开左侧的 **Agent**，找到要使用的 Agent。
2. 点击该 Agent 的**聊一下**操作，进入对话。
3. 在输入框中填写请求并发送。回复和工具调用会出现在时间线中。
4. 后续消息继续使用当前对话。查看已有对话时，打开左侧的**对话**并选择相应记录。

发送消息前，Agent 必须已启用，执行设备和模型也必须可用。运行需要人工决定时，在对话中的请求卡片上处理，或打开左侧的**收件箱**。

## 共享一条对话

共享对话是同一条对话的独立访问页面，保留相同的消息历史；它不会复制一份新对话。

1. 在左侧的**对话**中找到要共享的记录。
2. 点击该行的链接图标，悬停提示为**复制分享链接**。
3. 将复制的链接发给同一工作区的成员。链接形式为 `https://你的服务地址/c/对话ID`。
4. 对方登录后打开链接，即可在没有管理侧栏的页面查看同一条对话。所有者、管理员和成员可以继续发送消息；访客（`viewer`）只能查看。

链接本身不授予权限。未加入工作区的人不能因为拿到链接而读取消息；把 Agent 设为公开也不会公开它已有的对话。工作区成员可以读取工作区中的对话，因此不要在普通消息中填写密码或 API Key。

## 回答 Agent 的请求

权限请求会列出待执行操作和允许、拒绝选项；提问卡片会列出问题、选项和允许填写的回答框。选择答案后提交，Agent 收到决定后继续执行。已处理或已过期的请求不能重复作答。

**秘密回答**指 Agent 将某个问题标记为敏感回答时的输入方式，例如要求提供一段临时口令。该问题的自由文本框使用密码输入框，输入时显示圆点。普通消息和普通回答框不会自动变成秘密回答。

提交后，明文会传给正在等待的 Agent，保存的交互答案用 `[REDACTED]` 替代，交互记录和审计记录不展示原值。这个保护针对回答的传递和记录；不要要求 Agent 在后续回复或文件中复述秘密。

## 提及另一个 Agent

当前输入框没有 `@` 自动补全菜单。要指定另一个 Agent，直接输入 `@` 加上它在当前工作区中的完整名称或 slug，然后输入请求，例如：

```text
@reviewer 请检查这次修改的风险。
```

`@` 后支持中文、字母、数字、下划线和连字符，不支持空格。名称含空格时使用 slug。`@` 应放在消息开头，或放在空格、括号、中文标点之后。

- 没有提及文本时，消息交给对话绑定的 Agent。
- 提及了多个有效 Agent 时，每个 Agent 分别创建一个 Run；重复目标只执行一次。
- 名称拼错或目标已停用时，该提及不会创建 Run。消息中已有提及文本时，不会自动改发给默认 Agent。

发送后打开**运行**，检查 Agent 列是否为预期目标。聊天平台中的 `@机器人` 使用平台自己的提及功能，见[聊天集成](/zh/integrations)。
