title: 对话与共享对话
description: 使用 Agent 对话、保留上下文，并安全地共享访问入口。
---

Conversation 是用户与 Agent 交互时看到的上下文。消息、Agent 回复、Run 引用和交互请求都会保留在对话时间线中。

## 开始对话

在 Agent 页面点击**聊天**即可创建对话。每条消息可能创建一个或多个 Agent Run，具体取决于选中的 Agent 和连接器行为。Run 进行时，结果会流式写入时间线。

对话历史不等于 Run transcript。时间线展示协作上下文；Run 详情展示某一次执行的证据，包括工具事件、Runtime 快照、产物和用量。

## 上下文和边界

当前工作区是授权边界的一部分。用户只能读取自己所属工作区且 API 允许访问的 Conversation。每当消息会启动 Run 时，服务端还会再次检查 Agent Access。

修改 Agent 配置不会重写旧消息。历史消息和 Run 快照保留当次执行实际使用的配置。

## 共享对话

Parsar 支持通过共享对话入口访问已有 Conversation。共享不会复制对话，也不会创建新的 Agent；访问者仍必须通过服务端的工作区成员和权限检查。

共享链接应当视为工作区数据的访问指针。要撤销访问，应移除成员关系或调整 Agent/工作区策略，不要依赖 URL 的隐蔽性。

## 交互请求

当 Agent 请求权限或要求用户选择时，请求会同时出现在对话和**审批**页面。处理结果会记录解析来源并关联到对应 Run。秘密回答不会进入普通日志或 API 读取结果。

## 提及 Agent

在 Web Conversation 中，可以使用 `@name` 或 `@slug` 提及处于活动状态的 Agent。Parsar 会在当前工作区解析提及，忽略未知、非活动、自身以及重复目标，并为每个解析出的 Agent 创建独立 Run。因此提及不仅是文本格式，它会真正触发执行。

Agent 之间的调用只有在工作区和 Agent 策略允许时才会执行。默认最大调用链深度为 3，用于防止意外提及循环创建无限 Run。在飞书、Slack、Teams 和 Discord 群聊中，机器人必须被提及才会接收并触发入站工作；线程激活后，是否需要每条消息再次提及由对应频道适配器规则决定。

## 排查

- 没有回复：检查 Agent 是否 active、是否绑定 Runtime、凭据是否有效。
- Run 一直排队：检查 Runtime 在线状态和 daemon 配对。
- Conversation 无法访问：确认工作区成员关系和 URL。
- 输出不完整：打开 Run 详情检查事件和产物，不要只依赖最终消息。
