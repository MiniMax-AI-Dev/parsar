## The rules (from the user; binding)
- **Family design.** Pages compose the shared primitives in `src/components/ui/` and the shell in `src/components/layout/`; they do not restyle them with className overrides beyond layout (width, margin, grid placement). If a page needs a variant the primitive lacks, add the variant to the primitive (small, general) and use it, rather than styling locally.
- **One control per semantic per screen.** No duplicate buttons (header CTA + empty-state CTA, header + table footer), no duplicate nav/utility entries, no count shown twice.
- **No helper copy.** No page descriptions/subtitles, no keyboard-hint text, no version strings, no explanatory paragraphs that are neither content nor a control. Empty-state descriptions of one sentence are allowed. Form field hints that explain a required format are content and stay.
- **Type system.** Sizes only from the eight-tick scale, and on console surfaces only 20 (page title, `PageHeader`) / 14 (`text-base`, body & nav) / 13 (`text-sm`, rows, buttons, inputs, values) / 12 (`text-xs`, labels & metadata, mono). Weights: 600 page title only (`PageHeader` does it); 500 = names of things, active nav/tab, button labels, section heads; everything else 400. Never 700 (`font-bold`), never `font-semibold` outside PageHeader.
- **Two greys.** Text is `text-fg` (content, values, names, actions) or `text-fg-muted` (labels, metadata, placeholders, inactive). Replace `text-fg-subtle` / `text-fg-faint` / `text-fg-emphasis` with one of those two. Never colour text to signal state (`text-danger`, `text-success`, `text-warning`, `text-info` on words): state lives in the 14px `StatusIcon` or a `Badge` dot; the word stays in ink.
- **Icon-only status.** Use `StatusIcon` (queued / running / completed / failed / cancelled / interrupted) for run-like states; `Badge` with `dot` for other states; never a coloured chip with coloured text. Success/danger/warning tinted boxes (`bg-*-subtle`, `border-*-border`) are gone: an inline message is a 14px `AlertTriangle` in `text-status-failed` plus ink text (see `ErrorState`).
- **No cards.** No `rounded-lg border border-line bg-surface p-4` containers, no stat tiles, no nested bordered boxes, no `shadow-*` on rows/panels. Structure comes from hairlines (`border-b border-line`) and one tone step (`bg-surface-subtle` for side panels only). Sections inside a page are separated by spacing and a 12px/500 head (`RailSection` in a rail; on a page, an `h2` at `text-sm font-medium` with `mt-6`).
- **Lists are ledgers.** Any list of objects becomes `Ledger` + `LedgerHeader` + `LedgerRow` (+ `LedgerGroup` when a natural grouping exists) with the column template passed once, ids in `LedgerId`, numbers in `LedgerNum`, people/agents with `InitialTile`. HTML `Table*` is acceptable for truly tabular data (many equal columns) and already carries the ledger look. Detail views use `DetailRail` + `PropertyList`/`Property`, or, when the page is a full-page detail, `PropertyList` in the main column with `RailSection`-style heads.
- **Forms.** `Input` (28px), labels `text-xs text-fg-muted` above the field, 12px gap between fields, buttons right-aligned in a footer row with a top hairline. Selects/textarea should match `Input` (28px / 6px radius / hairline-strong border / control shadow); if none exists in `ui/`, add `select.tsx` / `textarea.tsx` mirroring `input.tsx`.
- **Dialogs.** Use `ui/dialog.tsx` and `alert-dialog.tsx`; restyle them once in the primitive if they still carry the old look (8px radius, hairline, floating shadow `app-shadow-floating`, 16px padding, title `text-sm font-medium`, footer with top hairline and outline/primary buttons). Do not restyle per dialog.
- **Motion.** Rely on the shared button transition and the `animate-pop-in` / `animate-rail-in` utilities; do not add new keyframes; never `transition-all` or `duration-300 ease-in-out`; never `animate-ping`/`animate-pulse` except `Skeleton` and `Badge pulse`.
- **Tokens only.** Never raw palette classes (lint fails). Never arbitrary text sizes. Widths/heights like `w-[232px]` are fine.
- **Copy.** Keep every existing i18n key and meaning. Do not rewrite factual copy. If you must add a key, use `python3 .impeccable/review/i18n-add.py <admin|common> <dotted.key> "<en>" "<zh>"` (it is file-locked; never edit the locale JSON by hand: other agents write to it concurrently).
- **Conversations page:** the user said it is not the product's focus; make it conform to the system plainly (shell, type, greys, no cards, unique controls). Do not invent a new concept for it.
